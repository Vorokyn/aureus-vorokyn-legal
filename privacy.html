2. Information that may be processed

Depending on the features a server enables, Aureus may process the following:

  • Discord identifiers: server, channel, member, and moderator IDs needed to apply configuration and carry out commands.
  • Warnings: record ID, server ID, member ID, moderator ID, reason entered by the moderator, and creation timestamp.
  • Server configuration: selected log channel, welcome channel, welcome-message template, and configured blocked-word rules.
  • Join-event information: data available from Discord member events, including account creation time, used for account-age checks and join-burst detection.
  • Message content for filtering: content may be inspected in memory to check for a configured blocked-word match. The shipped implementation does not intentionally save the entire matching message into a separate archive; a filter log records that a rule matched, rather than copying the message text.
  • Operational logs: application errors and runtime metadata. The hosting provider may separately keep technical logs, potentially including network metadata.
  • Support information: details you voluntarily provide in a public issue or support conversation.

3. Purposes and legal basis

Information is used to operate the Bot; retain server settings and warning records; apply actions requested by server moderators; send welcomes; check configured join patterns; apply blocked-word filters; secure the service; diagnose failures or abuse; and respond to support requests. The operator must determine and document a suitable lawful basis under the privacy laws that apply to the deployment. A server operator should also tell members about relevant moderation, logging, and filtering practices.

4. Storage, retention, and deletion

The starter implementation stores server settings and warnings in a local SQLite database at the path configured by the operator. The database persists until the operator clears records or deletes the database. There is no automatic warning-expiration job in this version. Members with appropriate server permissions can ask the server’s moderation team about warning records; the bot includes a moderator command to clear warnings for a member.

Application logs may be written to standard output and/or sent to a configured Discord log channel. Retention of Discord messages, hosting logs, backups, and support tickets depends on the server administrator and infrastructure provider. Operators should set a retention schedule, restrict access, and delete information that is no longer needed.

5. Sharing and disclosure

The Bot communicates with Discord to perform its functions. The project code does not intentionally sell personal information or provide a separate user database to advertisers. Infrastructure and hosting providers may process operational data. Moderators who can access a configured log channel may see events posted there. Discord handles information according to its own policies. This does not guarantee that every operator running a self-hosted copy follows this policy.

6. Permissions, intents, and message filtering

Member events are used for welcome messages and join-event checks. Blocked-word filtering requires Discord’s Message Content Intent to be enabled in the Developer Portal and made available by the bot’s code/configuration. The maintainer must test intent configuration after changes. Do not enable message filtering unless the server has decided it is appropriate and has provided any notices required by applicable law or its rules.

Blocked-word matching is simple case-insensitive substring matching. It can have false positives, such as matching a short entry inside a larger word. Server administrators choose the configured rules and should review complaints or mistaken deletions.

7. Security practices

Protect the bot token like a password; store secrets in environment variables or a secrets manager; use least-privilege permissions; restrict access to the database, host, and logs; keep dependencies updated; and review backups. No software or transmission method can be guaranteed perfectly secure. If a token is exposed, reset it immediately in the Discord Developer Portal and review relevant audit logs.

8. Requests and privacy rights

For a running deployment, contact the operator using the contact information at the top of this page. Requests for access, correction, deletion, restriction, or other privacy rights will be reviewed as required by applicable law. Some records may be needed for moderation integrity, abuse prevention, or legal obligations; the operator should assess each request under the law that applies.

The starter bot does not include an end-user self-service personal-data export tool. For self-hosted deployments, the person or organization operating the bot controls the database and must handle requests for that deployment.

9. Children and minors

Discord’s account requirements apply. The operator must assess applicable legal requirements when a server includes minors and must not collect additional information without an appropriate lawful basis and safeguards.

10. International data transfers

The operator’s hosting location, Discord infrastructure, repository provider, and support provider may be in different countries. The operator should assess any cross-border transfer rules applicable to their deployment.

11. Policy updates

This policy may be updated when the Bot’s functionality or data practices change. The operator should update the date and provide a change summary for material revisions. Review this policy whenever new commands, databases, logging, analytics, or integrations are added.
