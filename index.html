Suggested first checks

Quick troubleshooting

  • 01Slash command missing?
    Confirm the bot was invited with the applications.commands scope, command sync succeeded, and the command has propagated. Guild-specific sync is quicker for development.
  • 02Moderation action failed?
    Check the bot’s permission in that channel and make sure its highest role is above the target member’s role. Discord role hierarchy can block an action even when a permission is granted.
  • 03Welcome messages not appearing?
    Verify the welcome channel is configured, the bot can view and send in it, and the Server Members Intent is enabled in the Developer Portal.
  • 04Blocked-word filter not firing?
    Check the server’s configured rules, global configuration, Message Content Intent, and the relevant Developer Portal intent. The filter uses substring matching and may also create false positives.
  • 05Raid alerts confusing?
    Join-rate alerts are heuristic indicators. Review server audit logs and membership activity; do not assume every burst is malicious.

Bug report checklist

Include only what is needed to reproduce and diagnose the issue. Redact user-specific details and credentials.

  • Bot version: e.g. 0.1.0
  • Python/runtime and hosting: version, platform, and whether Docker is used
  • Command or feature: the affected command/event
  • Expected behavior: what you thought should happen
  • Actual behavior: what happened instead
  • Reproduction steps: a minimal sequence, ideally on a test server
  • Relevant logs: timestamps and stack traces with tokens and personal information removed
  • Permissions/intents: the relevant permissions and intents enabled

Security reporting

If you discover a vulnerability that could expose secrets, bypass moderator permissions, or enable raids, avoid disclosing exploit details in a public issue before the maintainer has had a reasonable chance to assess it. Contact the maintainer directly and provide a concise description, impact, reproduction details where safe, and a way to follow up.

Security reporting: Do not post exploitable details or credentials in public issues. Contact @vorokynn privately on Discord where possible. If GitHub displays a private “Report a vulnerability” option for the repository, that can also be used.

Support expectations

Support is best-effort, not a guaranteed response-time service. Maintainers may request further non-sensitive diagnostic details, merge duplicate reports, or decline assistance for unsupported modifications and hosting environments. Be respectful and avoid posting private conversations or unrelated personal information.
